# Independent work-sample instructions

These nine static tools demonstrate bounded frontend and data-QA work.
They were built with AI assistance from dated public observations.
They are not commissioned client projects or deployed fixes on company systems.
All sample customer/meeting inputs are synthetic unless explicitly sourced.
No revenue, conversion or time-saving outcome has been verified.

## Work

- Read this folder's README.md and the selected sample's README.txt first.
- Each sample has its own HTML entry point and local assets.
- Run `node run-tests.cjs` from this folder, or the sample's documented test command.
- Node.js 20+ is sufficient for the logic tests; no package installation is needed.
- Open the relevant index.html in a normal browser for visual and interaction review.
- Keep changes small and preserve the source facts, observation date and uncertainty labels.
- Use textContent or safe text nodes for user-supplied values.
- Do not introduce external scripts, analytics, API calls, live form submissions or credentials.
- Do not infer a correct part number, compatibility, customer traffic, lost sales or savings.
- Do not copy company designs, logos, private documents or testimonials.
- Keep synthetic fixture failures visibly separate from actual observations.
- Do not change a company site or send a message as a side effect of running a sample.
- Any outreach must use the separate current campaign ledger and its authorization/status checks.

## Done

The relevant tests pass, the intended interaction has been inspected in a browser,
all source and truth labels remain accurate, no unintended network request occurs,
and the handoff reports exactly what was verified and what remains unknown.
