# Security policy

Proofline is a static fictional sample. It has no backend, credential handling,
authentication, user data, analytics, or production release permission.

Do not add real customer records, private release evidence, credentials, tokens,
internal URLs, or proprietary requirements to examples, screenshots, issues, or
pull requests.

Report suspected vulnerabilities or accidental secret exposure through a
private GitHub security advisory. Do not publish sensitive reproduction details
in an issue. Revoke any exposed credential at its provider before repository
cleanup.

A production version would require authenticated users, authorization by role,
server-side validation, durable audit history, evidence integrity, retention and
privacy rules, rate limiting, monitoring, backups, and a separately authorized
deployment action.
